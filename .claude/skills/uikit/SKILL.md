# UIkit

**Appearance is classes. Behaviour is attributes.** `class="uk-card uk-card-default"`
styles; `uk-modal`, `uk-sticky`, `uk-grid` switch on JavaScript, configured inline as
`uk-sticky="offset: 50"`. UIkit auto-initialises and watches the DOM — you almost never
write JavaScript.

## Look names up; never recall them

```
node .claude/skills/uikit/bin/uikit.mjs <command>
```

| need | command |
|---|---|
| verify markup you wrote | `check <file.html> [--fragment]` |
| a component's real options and classes | `show uk-lightbox` |
| does this name exist? | `find thumbnav` |
| working markup for something | `example lightbox thumbnav` |
| theming | `vars card` (no argument = the globals that drive everything) |
| icon names | `icons arrow` |

**Run `check` on every HTML file you write or edit, before you report finishing.**
It resolves every `uk-*` name against the framework source, so it catches invented
classes, invented options and wrong breakpoints that read perfectly plausibly.

If a name does not come back from `find` or `show`, it does not exist. Search again
with different words — do not fall back to a plausible-looking guess.

## Before writing custom CSS or JS, stop

The single most expensive mistake with UIkit is hand-building something it already
ships — 60 lines of gradients and scroll listeners where one attribute would do.
Check the map below and `find` first. Spacing, alignment, flex, grid, visibility,
transitions and responsive behaviour are all utilities; there is very little a UIkit
page legitimately needs custom CSS for.

## Layout

Container → Grid → Width. `uk-grid` **must be the attribute** (`<div uk-grid>`); as a
bare class it never gets its gutters or row wrapping. `uk-child-width-*` goes on the
same element as that attribute; `uk-width-*` goes on its children.

Breakpoints are only `@s @m @l @xl` — base class first, then scale up.
`uk-child-width-1-2@s uk-child-width-1-3@m` means one column on phones.

Page rhythm, as the UIkit site itself is built:

- Alternate `uk-section uk-section-default` / `-muted` / `-primary`, sized with
  `uk-section-large` or `-xlarge`, each wrapping one `uk-container`.
- Fuse two sections into one visual block with `uk-padding-remove-top` on the second.
- Centred intro: `<div class="uk-width-xlarge uk-margin-auto uk-text-center">`.
- Eyebrow over headline: `<h1 class="uk-h6 uk-margin-remove">` then
  `<h2 class="uk-h1 uk-margin-top">` — `uk-h1…uk-h6` set visual size independently of
  heading level, so semantics stay correct.
- Alignment that changes with width: `uk-text-center uk-text-left@l`.
- Equal-height cards: `uk-grid-match` on the grid.
- Hover overlay: `uk-inline uk-transition-toggle` outside,
  `uk-position-cover uk-transition-fade` on the layer.

## Facts that are easy to get wrong

- **Icons need their own script.** Load `uikit.min.css`, `uikit.min.js` **and**
  `uikit-icons.min.js`. Without the third, every icon renders empty.
- **Dark surfaces mostly invert themselves.** `uk-section-primary`,
  `uk-section-secondary`, `uk-tile-primary/secondary`, `uk-card-primary/secondary`,
  `uk-overlay-primary` and `uk-offcanvas-bar` already set `--uk-inverse: light`.
  Add `uk-light` only over an *arbitrary* dark background — a background image or a
  custom colour. Use `uk-preserve-color` to opt a subtree out.
- **`uk-toggle`, `uk-switcher`, `uk-scroll`** replace click handlers. Their `target`
  must match an element that exists on the page.
- There is no `uk-text-white`, no `@md`, no `@lg`. `check` will tell you.

## Theming

Override UIkit's LESS/SCSS variables rather than writing CSS that fights the compiled
output. `vars` with no argument prints the ~49 globals (`@global-primary-background`,
`@global-font-size`, the breakpoints) which cascade into every component; `vars card`
prints that component's own. SCSS uses the same names with `$` instead of `@`.

## Inside Vue / React / htmx

UIkit observes `document` for added nodes, removed nodes **and attribute changes**, so
markup rendered later initialises itself, unmounted markup tears itself down, and an
attribute bound to reactive state creates or destroys its component as it flips. You
rarely need lifecycle code. `frameworks.md` covers the rest: JSX's valueless-attribute
quirk, the imperative API, `UIkit.use(Icons)` in a bundled setup, and the scoped build
for coexisting with another CSS framework.
